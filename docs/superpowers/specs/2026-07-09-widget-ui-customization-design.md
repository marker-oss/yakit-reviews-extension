# Настройка UI виджета + доведение дефолтного UI — дизайн

Дата: 2026-07-09
Ветка кода: `main` (HEAD `208bff9`)
Область: `web/reviews-widget` (виджет, loader), схема `WidgetConfig`
(`web/admin/src/widgetConfig.ts` + Go-сторона), страница «Редактор» админки.

## Цель

Сделать внешний вид виджета настраиваемым для продавца и довести дефолтный UI
до качества, с которым не стыдно идти к другим продавцам Кита. Модель
кастомизации — три слоя, каждый для своей аудитории:

1. **Крутилки в админке** — обычный продавец без CSS/JS. Выбирает 1–2 цвета,
   шрифт, раскладку — получает целостную тему.
2. **`customCss`** — продавец с верстальщиком. Пишет CSS поверх
   документированных `--rw-*`-токенов.
3. **Headless** — разработчик-интегратор. Публичный API уже существует
   (`/api/reviews`, `/api/showcase`, `/api/widget-config`), документируем его
   как поддерживаемый способ написать полностью свой рендер.

Порядок работ: **Фаза A** (доделать дефолтный UI — этот документ в деталях) →
**Фаза B** (пресеты тем в редакторе) → **Фаза C** (`customCss`) → **Фаза D**
(headless-доки). Фазы B–D описаны кратко, детализируются своими планами.

## Не-цели (YAGNI)

- Визуальный редизайн — **не** делаем. Направление: эволюция текущего тёплого
  стиля, полировка деталей. Дефолт должен прилично выглядеть и вне shegida.
- Drag-and-drop конструктор блоков виджета — нет.
- Переводы/мультиязычность виджета — нет (аудитория русскоязычная).
- Реализация Q&A-контента — отдельный roadmap
  (`2026-06-30-replies-qa-dsr-roadmap.md`); здесь только empty state вкладки.
- Замена нативного `<select>` сортировки на кастомный дропдаун — нет
  (гайдлайн `system-controls`: нативные контролы доступнее); стилизуем только
  закрытое состояние.

## Зафиксированные решения

1. **Производные цвета считает JS** при монтировании (не CSS `color-mix()` —
   старые WebView покупателей получат сломанные цвета; не 25 крутилок — анти-UX).
2. **Стиль — эволюция текущего**: фиолетовый акцент и Onest остаются дефолтом.
3. **Шрифты — курируемый список, self-hosted**. Никакого Google Fonts CDN на
   страницах магазинов (последовательно с позицией 152-ФЗ: не сливаем IP
   покупателей Google; тот же довод, что для админки в спеке 2026-07-06).
   woff2-сабсеты (latin+cyrillic) лежат на сервере отзывов, loader вставляет
   `<link>` на свой же origin.
4. **Аудит зафиксирован скриншотами** (14 конфигураций, headless Chromium),
   артефакты в scratchpad `uiaudit/`; матрица повторяется как критерий приёмки.

## Фаза A: доделать дефолтный UI

### A1. Темизация

**Конфиг.** `theme` получает одно новое поле: `star` (цвет звёзд, дефолт
`#c99a3f`). Остальное без изменений: `accent`, `accentInk`, `text`, `muted`,
`panel`, `border`, `dark`.

**Производные в JS.** В `applyTheme` (`reviews-widget.js:1416`) добавляется
цветовая математика (hex → RGB → смешивание в sRGB, ~30 строк):

| Токен | Формула (light) | Сейчас |
|---|---|---|
| `--rw-accent-hover` | accent ⊕ 15% чёрного | захардкожен `#583b78` |
| `--rw-accent-tint` | accent 12% ⊕ panel 88% | захардкожен `#efebf5` |
| `--rw-accent-tint-2` | accent 24% ⊕ panel 76% | захардкожен `#ded6ec` |
| `--rw-soft` | text 4% ⊕ panel 96% | захардкожен `#f4efea` |
| `--rw-soft-muted` | muted 55% ⊕ panel 45% | захардкожен `#9a93a1` |
| `--rw-shadow-sm/md` | альфа-тени от text/accent | фиолетовый отлив |
| `--rw-trust-tint` | trust 10% ⊕ panel 90% | захардкожен `#e9f1ec` |
| `--rw-star` | из конфига | захардкожен `#c99a3f` |

`--rw-trust` и `--rw-danger` остаются системными (семантика, не бренд).

**Оживить `theme.dark`** (сейчас поле мёртвое — виджет его не читает, в CSS
прибит `color-scheme: light`): при `dark: true` — `color-scheme: dark` из JS,
производные переворачиваются (hover = осветление, тени глубже), и если
продавец не переопределил text/panel/border/muted — подставляются тёмные
дефолты. Скриншот-доказательство поломки: `dark-attempt-desktop.png` (невидимые
имена, светлые плашки плюсов/минусов со светлым текстом, белый select).

**Шрифты.** В админке `fontFamily` из текстового поля становится списком из
~8 кириллических вариантов (Onest — дефолт, Inter, Manrope, Golos Text,
PT Sans, Rubik, Jost, системный стек). Сабсеты self-hosted (см. решение 3),
`font-display: swap`. Loader вставляет `<link>` в `document` (внутри shadow
DOM `@font-face` не работает; механизм `ensureDocumentStyle` уже есть).
Свободный ввод остаётся как продвинутый override без загрузки. `@import`
Google Fonts из `reviews-widget.css` удаляется.

**Админка.** Секция «Тема» редактора: главные крутилки — accent, dark, шрифт;
text/muted/panel/border/star — в свёрнутом блоке «Тонкая настройка».
Предпросмотр не требует доработок (гоняет тот же widget JS).

**Совместимость.** Старые конфиги работают без миграции: `star` домердживается
дефолтом, производные в конфиге никогда не жили.

## Фаза B: пресеты тем в редакторе (кратко)

Пресет = именованный бандл значений `theme` + `typography` (+ опционально
`layout`). Галерея карточек-миниатюр в «Редакторе» («Шегида», «Минимал»,
«Тёмный», «Контраст», …); клик заполняет форму, дальше продавец твикает
руками. Пресеты — статические данные в admin SPA; виджет о них не знает,
код-путей не добавляется. Детальный план — при старте фазы.

## Фаза C: `customCss` (кратко)

Поле `customCss: string` в `WidgetConfig` (лимит ~20 КБ, экранирование
`</style>`). Сервер отдаёт его в `/api/widget-config`, виджет вставляет
`<style>` последним в shadow root — каскад продавца выигрывает у дефолтов.
Ограничение Кита обходится само: CSS приезжает с нашего сервера, на страницу
магазина ничего вставлять не нужно. В админке — textarea в «продвинутом»
блоке с тем же live-предпросмотром. Публикуем справочник `--rw-*`-токенов и
стабильных классов. Риск — самострел продавца; мера — кнопка «Сбросить».

## Фаза D: headless-доки (кратко)

Раздел в README/docs: публичные эндпоинты, CORS (`REVIEWS_SHOP_ORIGIN`),

## Верификация (критерий приёмки фазы A)

Повторить скриншот-матрицу аудита тем же способом (headless Chromium,
`scratchpad/uiaudit/gen*.sh`):

- конфигурации: default, grid, carousel, accent-blue, **dark**, empty,
  longtext, minimal, compact, submit (desktop+mobile), questions, lightbox;
- ширины: 1280 и 375;
- плюс живой браузер: hover/focus-visible, лайтбокс (Esc, фокус-трап, свайп),
  отправка формы (ошибки валидации, успех).

Приёмка по чек-листу: тёмная тема читаема (контраст 4.5:1), смена accent не
оставляет фиолетовых следов, на 375px нет горизонтального скролла и обрезанных
чипов, тач-таргеты ≥44px, у карусели есть видимая навигация, у пустых
состояний — CTA. Существующие тесты `web/reviews-widget/test/` зелёные;
новая логика (цветовая математика, line-clamp-тогглы) покрывается там же.

## Риски

- Цветовая математика в JS должна давать пиксельно те же значения в админ-
  предпросмотре и на проде — гарантируется общим кодом (один `applyTheme`).
- Изменение дефолтной вёрстки карточек заденет прод shegida — прогнать
  скриншот-сравнение на реальных данных перед релизом.
- Self-hosted шрифты увеличивают репозиторий/образ — брать только latin+cyrillic
  сабсеты (прецедент: admin, коммит `dcc5480`).
