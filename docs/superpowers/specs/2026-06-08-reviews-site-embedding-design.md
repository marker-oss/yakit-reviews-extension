# Reviews — встраивание отзывов на сайт (Яндекс Кит) через YTM

**Дата:** 2026-06-08 · **Статус:** дизайн (на согласование) · **Связанные доки:**

## 1. Цель и охват

На страницах товара витрины `shegida.ru` (платформа — Яндекс Кит) показывать
бесшовный, выглядящий нативно блок отзывов **по конкретному товару**, матчинг —
по артикулу продавца. Дополнительно встраивать `schema.org`-разметку
(`aggregateRating` + отзывы) для звёзд рейтинга в поисковой выдаче.

Это первый трек интеграции витрины: только **просмотр** отзывов.

### В охвате (MVP)

- Блок отзывов на странице товара (`/products/...`), агрегация по артикулу.
- Сводка: средний рейтинг и количество отзывов.
- Список отзывов: автор, дата, оценка, текст, плюсы/минусы, медиа-превью,
  ответ продавца (если импортирован).
- Инъекция JSON-LD `aggregateRating` + ограниченного набора отзывов для SEO.
- Доставка данных статическим JSON; встраивание — через Яндекс Тег Менеджер.

### Вне охвата

- Общая страница «все отзывы о магазине».
- Живой публичный API (в горячем пути браузера его нет — только статика).
- Постинг ответов обратно на маркетплейсы.
- Несколько витрин/магазинов, мультитенант.
- Локальное кеширование медиа-байтов (храним только URL на CDN маркетплейса).
- Сбор YM/Ozon — отдельный трек коллектора (здесь данные только из того, что
  уже собрано; на старте — WB).

## 2. Реалии платформы (по разбору живого DOM)

Разобрана реальная страница товара `https://shegida.ru/products/svitshot-hlopkovyiy-100954`.

- **Платформа — Яндекс Кит.** React/Redux SPA с серверным рендерингом: контент
  присутствует в HTML, гидрация на клиенте.
- **Классы — хешированные CSS-модули** (`SectionLayoutRow_root__mf3YC`,
  `YandexKitModule_module__I1nug`). Меняются между билдами Кита. **Нельзя**
  использовать классы как селекторы-якоря.
- **Нативного блока отзывов нет.** Текущий «блок отзывов» на странице — это
  ручной текст продавца со ссылкой на WB. JSON-LD товара идёт без
  `aggregateRating`.
- **Ключ агрегации присутствует в странице.** В состоянии/DOM лежит
  `"sku":"107"`; `107` в `data/shegida-product-links.json` указывает ровно на
  эту страницу. Значит схема «прочитать артикул из DOM → подтянуть отзывы по
  артикулу → отрендерить» рабочая.
- **Страница = вертикальный стек секций** (`SectionLayoutRow`); якоримся по
  структуре/тексту/URL, не по классам.

## 3. Вектор встраивания: Яндекс Тег Менеджер (YTM)

Доступный канал внедрения кода на сайт Кита — **Яндекс Тег Менеджер**,
встроенный в Яндекс Метрику (включается владельцем счётчика).

- Тип тега **«Пользовательский HTML»** позволяет выполнять произвольный HTML/JS
  по триггеру.
- Триггеры: просмотр страницы, клики, изменение URL. **Явной поддержки
  SPA-history-навигации нет.**
- ⚠️ **Риск: Sandboxed JavaScript.** YTM заявляет изоляцию кода. Реальные
  ограничения «Пользовательского HTML» на доступ к DOM нужно **проверить
  эмпирически** (см. тест-лестницу). Если DOM закрыт — fallback на iframe
  (вариант B, см. §7).

### Инвариант: YTM грузит loader один раз, дальше — наш скрипт

Раз SPA-триггеров в YTM нет, не полагаемся на повторное срабатывание тега на
каждом товаре. YTM срабатывает **один раз** и подгружает наш самодостаточный
`loader.js`. Всю последующую логику (навигация, переинъекция) держит loader.

## 4. Компоненты

### 4.1 `reviews export` (новая Go-команда)

Читает SQLite и пишет статические JSON-артефакты:

- `by-article/<article>.json` — отзывы + агрегат (средний рейтинг, количество)
  для одного нормализованного артикула.
- `index.json` — карта `артикул → {count, rating}` (для быстрых проверок «есть
  ли отзывы» без загрузки полного файла).

Нормализация артикула переиспользует логику из `discover-site-urls`
(`3467/Белый` → базовый `3467`); варианты одного товара агрегируются в один
артикул.

Публичный JSON-shape фиксируется здесь как контракт между бэком и `loader.js`
(точные поля — на этапе плана; основа — уже существующий ответ `/api/reviews`).

### 4.2 `loader.js`

Один самодостаточный скрипт, хостится на нашем домене, грузится YTM один раз.
Обязанности:

1. Установить SPA-наблюдатель: `MutationObserver` + перехват
   `history.pushState`/`popstate`, с дебаунсом.
2. На событии «страница товара устаканилась»: определить страницу товара
   (URL `/products/...`), извлечь артикул из DOM/состояния (`sku`), проверить
   идемпотентность (пропустить, если блок для этого артикула уже вставлен).
3. Запросить `by-article/<article>.json` (с кешем в памяти).
4. Найти якорь вставки по структуре/тексту (не по классам), вставить host-узел
   с **Shadow DOM**, отрендерить UI.
5. Инъектировать `<script type="application/ld+json">` с `aggregateRating` +
   ограниченным набором отзывов в `<head>` (только при ≥1 отзыве, кап ~10).

Идемпотентность: маркер-атрибут на host-узле + guard по текущему артикулу;
при смене товара — снять старый блок/обновить, вставить новый.

### 4.3 Переиспользование `web/reviews-widget`

Существующий прототип (`reviews-widget.js`, `reviews-widget.css`) рефакторим
так, чтобы он монтировался в shadow root и принимал датасет **одного артикула**
вместо полной выборки из БД. «Бесшовность» (шрифт, цвета, отступы под Кит)
воспроизводим вручную внутри shadow root; наследуем `font-family` страницы.

## 5. Поток данных

```text
WB-коллектор → SQLite → reviews export → статический JSON (HTTPS+CORS)
                                              │
                              loader.js (в странице, через YTM)
                                              │
                         Shadow DOM-блок отзывов + JSON-LD в <head>
```

## 6. Транспорт и деплой

### Транспорт

- **HTTPS обязателен.** Страница отдаётся по HTTPS; `fetch` на `http://` —
  mixed content, браузер блокирует. HTTP-вариант исключён.
- **CORS включён** на эндпоинте статики (поддомен cross-origin).

### Прод

- Один VPS, тариф **1 GB RAM / 1 CPU / 20 GB** — достаточно для Фазы 1
  (single store, WB, почасовой синк, статический export; медиа-байты не храним).
- На VPS: Go-сервис (collector + export) + **Caddy** (auto-TLS Let's Encrypt),
  Caddy отдаёт статический JSON и `loader.js` на поддомене.
- Бинарь **кросс-компилируем локально** (`GOOS=linux`) и заливаем артефакт —
  чтобы не упереться в 1 GB RAM при сборке на VPS.

### Тест

- Локальный `reviews serve`/`export` + туннель `cloudflared`/`ngrok` (даёт
  HTTPS-хостнейм без покупки домена). Этого достаточно для шагов 1–3
  тест-лестницы.

## 7. Ключевые решения и риски

- **Нестабильные классы Кита** → якоримся по структуре/тексту/URL; переинъекция
  идемпотентна (маркер-атрибут + guard по артикулу).
- **Песочница YTM** (главный риск) → проверяем эмпирически; fallback —
  **вариант B (iframe)**: вместо inline-блока вставляем `<iframe>` на нашу
  hosted-страницу виджета с авто-высотой через `postMessage`. Полная изоляция
  стилей ценой меньшей «нативности» и отсутствия SEO-разметки.
- **SPA-навигация** → переинъекцию держит loader, не YTM.
- **SEO JSON-LD** → только при ≥1 отзыве, кап встроенных отзывов (~10), по
  правилам rich-результатов Яндекса/Google.
- **Расхождение артикулов** → нормализация переиспользуется из
  `discover-site-urls`; нематчнутые артикулы просто не показывают блок (без
  ошибки в консоли).

## 8. Тестирование

Лестница от дешёвого к честному:

1. **Локально:** сохранённый HTML страницы + `loader.js` → проверка вёрстки.
   Быстро, но без живой React-гидрации.
2. **Букмарклет/консоль на живом сайте:** вставить `loader.js` в консоль на
   реальной странице товара → рендер на настоящем DOM, проверка переходов между
   товарами. Это 1-в-1 то, что сделает YTM, но без деплоя.
3. **Playwright / Chrome DevTools MCP (автоматически):** открыть товар,
   инъектнуть loader, скриншот, ассерты «блок присутствует» и «JSON-LD в head»,
   прогон перехода между двумя товарами (SPA).
4. **YTM preview:** финальная проверка реальной песочницы.

Тестовые данные на шагах 1–3 — локальный `export` через туннель или
закоммиченный sample JSON.

### Критерии готовности MVP

- На странице товара с известным артикулом появляется блок отзывов по этому
  товару, визуально согласованный со страницей.
- Переход между товарами (SPA) корректно обновляет блок без дублей.
- В `<head>` присутствует валидный JSON-LD `aggregateRating` при наличии
  отзывов.
- Данные приходят по HTTPS с CORS; HTTP-путь отсутствует.
- Артикул без отзывов не ломает страницу и не шумит в консоли.

## 9. Открытые вопросы

- Точный публичный JSON-shape (`by-article/<article>.json`) — фиксируется на
  этапе плана реализации.
- Конкретный поддомен/домен для прод-хостинга — выбирается при деплое.
