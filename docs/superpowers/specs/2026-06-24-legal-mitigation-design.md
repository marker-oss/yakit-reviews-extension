# Legal mitigation — design spec

**Date:** 2026-06-24
**Status:** Approved (brainstorming) — ready for implementation plan
**Scope chosen:** «Код + юр-обвязка» + полное удаление хранения ПД

## Контекст и цель

Reviews — самостоятельный Go-сервис, который тянет отзывы с маркетплейсов (WB, YM;
Ozon — лейбл без адаптера) официальными API, хранит их в локальной SQLite/PG, даёт
админ-панель для модерации и отдаёт клиентский JS-виджет для встраивания на сайт продавца.

Цель — закрыть юридические риски (152-ФЗ, реклама/ЗоЗПП, права на переопубликацию,
атрибуция) кодом и юридической обвязкой, и привести систему в соответствие с позицией
продавца «мы транслируем информацию с маркетплейса и не храним персональные данные».

Аудит подтвердил, что уже в порядке: поле `Raw` не утекает в публичный JSON
(`reviewjson.SellerArticleForReview` использует его только сервер-сайд), логи без ПД,
виджет чисто клиентский (отзывы не индексируются Google как контент продавца),
per-review source-label есть, лицензия Apache-2.0 чистая.

## Принятые решения (из брейншторма)

- **A2 имя автора:** «Имя + буква фамилии» («Анна К.»).
- **A1 блюр лиц:** везде (лента, карточка, лайтбокс), всегда включён, без тоггла.
- **A3 удаление по запросу:** контакт + ручное удаление админом; плюс hard-delete одной записи.
- **A4 политика конфиденциальности:** только шаблон-файл в репозитории.
- **Хранение ПД:** убираем полностью — анонимизация при записи, не на выдаче.

## Компоненты дизайна

### 1. Прокси изображений + блюр лиц (A1, C3)

Новый пакет `internal/mediaproxy`, маршрут `GET /media?u=<url-encoded CDN url>`.

- **Allowlist хостов** (конфиг `REVIEWS_MEDIA_ALLOWLIST`, дефолты: `*.wbbasket.ru`,
  `images.wildberries.ru`, `avatars.mds.yandex.net`) — защита от open-proxy/SSRF.
  Сверка по суффиксу хоста; нет в allowlist → 403.
- **Поток:** валидировать `u` → скачать байты (таймаут, лимит размера) → декод →
  детекция лиц **pigo** (чистый Go, без CGO; каскад `facefinder` встраиваем через `embed`) →
  gaussian/box-blur по найденным боксам (с небольшим расширением бокса) → энкод JPEG → отдать.
- **Кэш:** in-memory LRU с TTL (ключ — хеш URL). **Без диска и БД** — медиа не хранится.
  Размер кэша ограничен (конфиг).
- **Заголовки ответа:** `Cache-Control` для браузера, `Referrer-Policy: no-referrer`,
  CORS-заголовки для origin виджета (как у `/api/*`).
- **Fallback:** лицо не найдено → отдать перекодированный оригинал; ошибка декода/детекции →
  отдать оригинальные байты (картинка не пропадает, приватность деградирует мягко);
  ошибка скачивания → 502.
- **Виджет:** функция `proxyURL(u)` оборачивает `item.url` и `previewUrl` в 3 точках рендера
  ([:548](../../../web/reviews-widget/reviews-widget.js#L548),
  [:661](../../../web/reviews-widget/reviews-widget.js#L661),
  [:757](../../../web/reviews-widget/reviews-widget.js#L757)).
  База прокси выводится из `options.source` (origin сервера Reviews).

**Производительность:** `loading="lazy"` уже есть; кэш гасит повторы; обрабатываются только
видимые картинки. pigo быстрый, CPU-нагрузка приемлема.

**Тесты:** allowlist (allow/deny/SSRF), fallback-ветки, кэш-hit/miss, корректность заголовков;
блюр проверяем на фикстуре с известным лицом (бокс не пустой) и на картинке без лиц (pass-through).

### 2. Удаление хранения ПД (A2 + минимизация)

Анонимизация переносится **на уровень приёма** — ПД не попадают в БД.

- **Чокпоинт:** `store.UpsertReview` ([reviews.go:19](../../../internal/store/reviews.go#L19)).
  Нормализуем `input.AuthorName` в начале функции → используется и в insert ([:38](../../../internal/store/reviews.go#L38)),
  и в update ([:73](../../../internal/store/reviews.go#L73)).
- **Функция** `anonymizeAuthorName(full string) string`:
  - `"Анна Котова"` → `"Анна К."`
  - одно слово `"Анна"` → `"Анна"`
  - пусто → `""` (виджет уже подставляет «Покупатель»)
  - кириллица/латиница/дефисные фамилии корректно (первая графема второго токена + «.»).
- **Поле `Raw`:** перестаём писать (в `UpsertReview` пишем `Raw: ""`). Оба адаптера уже
  заполняют `SellerArticle` при приёме ([wb](../../../internal/marketplace/wb/client.go),
  [ym:219](../../../internal/marketplace/ym/client.go#L219)), так что `Raw` был лишь легаси-фолбэком.
  Колонку в схеме оставляем (nullable), чтобы не делать болезненную миграцию схемы.
- **`reviewjson`:** анонимизация на выдаче НЕ нужна (имя уже анонимно в БД). `AuthorName`
  передаётся как есть. `SellerArticleForReview` упрощается до возврата `SellerArticle`
  (Raw пустой → фолбэк всё равно вернёт ""); поведение для новых данных не меняется.
- **Что остаётся в БД (это контент, не идентификатор):** `Text`/`Pros`/`Cons`,
  `ExternalReviewID`/`ExternalProductID` (непрозрачные ID для дедупа и ссылок). В политике
  фиксируем, что текст отзыва публикуется в исходном виде с маркетплейса.

### 3. Миграция существующих данных

Одноразовый прогон при старте (идемпотентный, под флагом «выполнено»):

- Для всех строк: `AuthorName` → `anonymizeAuthorName(AuthorName)` (пропускать уже
  анонимизированные — эвристика «оканчивается на 1 букву + точку»).
- Для строк с пустым `SellerArticle` и непустым `Raw` (WB): извлечь `supplierArticle`,
  записать в `SellerArticle`.
- Очистить `Raw` → `""` во всех строках.

Прогон логирует количество обработанных строк (без ПД). Тест: фикстура из «грязных» строк →
после прогона имена анонимны, `Raw` пуст, `SellerArticle` сохранён.

### 4. Маркировка ответа продавца (B3)

- В `reviewjson.Answer` добавить поле `Kind string` (`"seller"` | `"marketplace"`).
  Заполняется в [reviewjson.go:61-69](../../../internal/reviewjson/reviewjson.go#L61):
  admin-reply → `"seller"`, ответ МП → `"marketplace"`.
- Виджет: при `kind === "seller"` подписывать блок «Ответ продавца», при `"marketplace"` —
  «Ответ магазина» (как сейчас). Не выдавать ответ продавца за контент маркетплейса.
- Тест `reviewjson`: admin-reply → `Kind == "seller"`; ответ МП → `Kind == "marketplace"`.

### 5. Атрибуция YM (C1)

- В `marketplaceProductURL` ([reviewjson.go:114](../../../internal/reviewjson/reviewjson.go#L114))
  добавить кейс `ym`: при непустом `ExternalProductID` →
  `https://market.yandex.ru/product/<urlPathEscape(id)>`.
- Пер-отзывного диплинка API YM не даёт — ссылка на товар достаточна для атрибуции.
  `marketplaceReviewURL` для YM возвращает product URL (без `#comments`).
- Тест: YM-отзыв → product URL построен; пустой ProductID → "".

### 6. Политика по скрытию отзывов (B1)

- В админ-UI рядом с действием hide — предупреждающий текст:
  «Скрытие — только для спама/мусора/дублей. Сокрытие негатива ради рейтинга — риск по
  ЗоЗПП и закону о рекламе (ФАС)».
- Раздел в доке (README или docs/legal) с той же политикой. Поведение фичи не меняем.

### 7. Шаблон политики конфиденциальности (A4)

Файл `docs/legal/privacy-policy-template.ru.md` с плейсхолдерами
(`{{OPERATOR_NAME}}`, `{{CONTACT_EMAIL}}`, `{{DOMAIN}}`). Покрывает: какие данные
обрабатываются и какие НЕ хранятся (имя анонимизировано, медиа не хранится, лица заблюрены),
источник (маркетплейсы по официальным API), цель, правовое основание, срок,
права субъекта (доступ/удаление), порядок запроса (контакт), упоминание блюра лиц.

### 8. Канал удаления по запросу субъекта (A3)

- env `REVIEWS_PRIVACY_CONTACT` (email/контакт) — подставляется в шаблон политики.
- Админ удаляет вручную существующим интерфейсом (soft-delete убирает из публичной выдачи).
- Для настоящего «стирания» — новое действие в админке **«Удалить навсегда»**
  (hard-delete одной записи + её `ReviewMedia`), отдельно от массового purge (вне scope).
  Маршрут под CSRF + сессией, как остальные admin-мутации.
- Тест store: hard-delete удаляет строку и связанные media; записи нет в выдаче и в админке.

### 9. Чек-лист прав в инсталляторе (C2)

- Экран-подтверждение в TUI-визарде (`internal/installer`): чекбокс/подтверждение
  «Подтверждаю, что имею право переопубликовывать отзывы со своих карточек и ознакомился
  с обязанностями оператора ПД (152-ФЗ)». Без подтверждения — установка не продолжается.
- Раздел «Юридический чек-лист» в README: права на API-токены, переопубликация,
  размещение политики конфиденциальности, контакт для запросов на удаление.

## Что НЕ входит (явно вне scope)

- Массовый hard-purge всех soft-deleted (A5).
- Регистрация оператора ПД в Роскомнадзоре (инструкция), формализованная политика модерации,
  аудит-лог админ-действий (это уровень «Максимум»).
- Реализация адаптера Ozon (его нет; только лейбл).
- Серверный рендер/SEO (не требуется — виджет клиентский).

## Затрагиваемые файлы (ориентир)

- Новое: `internal/mediaproxy/*`, `docs/legal/privacy-policy-template.ru.md`,
  миграция (`internal/store/` или `cmd`).
- Правки: `internal/store/reviews.go`, `internal/store/curation.go` (hard-delete),
  `internal/reviewjson/reviewjson.go`, `internal/server/server.go` (маршрут /media + admin hard-delete),
  `internal/config/config.go` (allowlist, privacy contact),
  `web/reviews-widget/reviews-widget.js` (proxyURL + подпись ответа),
  `internal/installer/*`, `README.md`.

## Критерии готовности

- Фото в виджете проходят через `/media` и лица заблюрены; allowlist отбивает чужие хосты.
- В БД (новые и мигрированные строки) нет полных имён и нет `Raw`; `SellerArticle` сохранён.
- Ответ продавца визуально отделён от ответа маркетплейса.
- YM-отзывы имеют ссылку на товар.
- Существует шаблон политики, env-контакт, hard-delete в админке, предупреждение по hide,
  экран-согласие в инсталляторе и чек-лист в README.
- Все новые/затронутые пути покрыты тестами; `go build ./...` и `go test ./...` зелёные.
