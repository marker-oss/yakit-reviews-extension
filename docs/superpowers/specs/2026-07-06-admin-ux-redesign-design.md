# Спринт: улучшение админки Reviews — дизайн

Дата: 2026-07-06
Ветка кода: `main` (HEAD `637c23c`)
Область: только `web/admin` (фронт) + средний объём бэкенда под диагностику.

## Цель

Поднять качество админ-панели по четырём направлениям:

1. **Новая дизайн-система** — уйти от «бутиковой» эстетики одного магазина к
   нейтрально-профессиональному SaaS-виду (продукт продвигается разным продавцам
   Яндекс Кита).
2. **Логика и компоновка настроек** — разгрузить перегруженный «Редактор»,
   навести порядок в структуре.
3. **Обратная связь при сохранении** — пользователь сразу понимает, что
   изменение **сохранилось** и **применилось** (это разные вещи).
4. **Диагностика «Состояние»** — на человеческом языке объяснять, что не так,
   почему виджета не видно и как починить.

## Не-цели (YAGNI)

- **Тёмная тема** — не делаем (решение пользователя).
- **Шаблоны ответов**, графики динамики на Сводке, горячие клавиши модерации —
  бэклог.
- **Постоянный журнал событий** (новая таблица в БД, запись во всех воркерах,
  Уровень 3 диагностики) — бэклог.
- **Слияние «Витрины» (Showcase) и «Отбора» редактора** в один механизм — бэклог;
  в этом спринте только переформулировка подписей, чтобы не путались.
- **Автосохранение** — отклонено, везде явная кнопка.
- Изменения виджета, публичных роутов, воркеров синхронизации, схемы БД — вне
  объёма (диагностика читает существующие данные, не меняет их).
- Google Fonts CDN — отказ, шрифт подключается локально.

## Зафиксированные решения

1. **Дизайн-направление:** нейтральный SaaS (индиго/синий акцент, Inter, плоские
   карточки, заметные тосты). Ориентир — Linear / Vercel / Stripe.
2. **Шрифт:** Inter, подключённый **локально через сборку** (`@fontsource/inter`),
   а не через Google Fonts CDN. Причина: self-host у разных продавцов, CDN —
   лишняя внешняя зависимость и вопрос приватности. Засечный Prata убирается,
   заголовки и текст — одним семейством, иерархия через размер/вес.
3. **Структура «Виджета»:** вкладки внутри одной страницы (вариант 1), а не
   разнесение по пунктам меню. Одна кнопка «Опубликовать», модель версий не
   ломается, постоянное превью справа.
4. **Механика сохранения:** явная кнопка «Сохранить/Опубликовать» везде (не
   автосохранение, не гибрид). Единообразно на всех экранах, дружит с
   версионированием конфига.
5. **Фичи спринта:** панель/страница «Состояние» (диагностика Уровень 2) +
   бейджи-счётчики в меню + переключатель превью desktop/mobile. Тёмная тема
   исключена.
6. **Глубина диагностики:** Уровень 2 — пассивный чек-лист + активные проверки
   (сервер сам тестирует сайт/резолв артикула/доступы МП). Читаемый журнал из
   существующих данных входит во все уровни.

## Текущее состояние (что есть)

**Стек админки:** React 19 + Vite 7 + TypeScript, без роутер-библиотеки
(hash-роутинг вручную в `App.tsx`), без стейт-менеджера, без UI-библиотеки. Стили
— один файл `web/admin/src/styles.css` (895 строк) на CSS-переменных `--admin-*`.
API-обёртки в `src/api.ts` (`apiGet`, `apiWrite` с CSRF).

**Текущая дизайн-система:** тёплый кремовый фон `#fbf8f4`, фиолетовый акцент
`#68478d`, шрифты Onest (текст) + Prata (засечный, заголовки) с Google Fonts CDN,
скруглённые карточки 12–16px.

**Навигация (`App.tsx`):** Сводка · Отзывы · Вопросы · Виджет (Витрина / Редактор
/ Встраивание) · Настройки (Общие / Маркетплейсы).

**Страницы:**
- `Dashboard.tsx` — статичные метрики (всего/показано/удалено/на модерации/средняя
  оценка), счётчики по МП, последние синхронизации.
- `Reviews.tsx` (718 строк) — богато: фильтры, поиск с подсветкой, массовые
  действия, лайтбокс медиа с клавиатурой, пагинация, инлайн-редактирование,
  ответы с публикацией на МП + повтор, закрепление на товар.
- `Questions.tsx` — ответы с публикацией на МП + повтор.
- `Editor.tsx` (352 строки) — **перегружен**: заголовок + цвета + шрифт/макет +
  видимость + отбор (фильтры/сортировка/ранжирование) + политика площадок +
  версии, всё одной простынёй. Публикует один версионируемый конфиг на контекст
  (`product` / `homepage`). Живое превью в iframe.
- `Showcase.tsx` — отдельный механизм: правило отбора отзывов для главной.
  Смысловое пересечение с «отбором» из редактора → путаница.
- `Embed.tsx` — сниппет для вставки (loader.js + REVIEWS_EMBED_CONFIG).
- `Settings.tsx` — URL согласия/правил, адрес магазина (CORS), sitemap, панель
  152-ФЗ (DSR).
- `Marketplaces.tsx` — доступы МП, включение, публикация ответов, обновление
  каталога, синхронизация.

**Обратная связь сейчас (главная проблема):** каждое действие ставит
малоконтрастный `<p className="muted">` («Сохранено», «Опубликована версия N»,
«Доступы сохранены»). Нет тостов, нет цвета, нет автоскрытия. **Нигде нет
индикатора несохранённых правок** — хуже всего в «Редакторе», где можно изменить
20 полей и не понять, опубликовал ли.

## Дизайн

### 1. Дизайн-система (токены)

Переписать слой переменных в `styles.css` на нейтральный SaaS-набор. Все значения
через токены, дальше компоненты не хардкодят цвета.

Палитра (ориентир, финально уточняется при реализации):

| Роль | Значение |
|---|---|
| Фон | `#f7f8fa` |
| Поверхность (карточки) | `#ffffff` |
| Границы | `#e5e7eb` |
| Текст основной | `#111827` |
| Текст приглушённый | `#6b7280` |
| Акцент | `#4f46e5` (hover `#4338ca`) |
| Акцент-подложка | `#eef2ff` |
| Успех | `#16a34a` |
| Предупреждение | `#d97706` |
| Ошибка | `#dc2626` |

- **Шрифт:** `@fontsource/inter` (варианты 400/500/600/700), импорт в `main.tsx`
  или CSS сборки; убрать `@import url(fonts.googleapis.com...)` и Prata.
- **Форма:** радиусы 8–10px (кнопки 8, карточки 10–12), тени мягче/тише, единая
  шкала отступов. Сохранить существующую сетку `.app-shell` (сайдбар + рабочая
  область) и адаптив.
- Существующие имена классов по возможности сохранить (меньше диффа в JSX),
  меняются значения токенов и точечно структура.

### 2. Реструктуризация «Виджета» (вкладки)

`Editor.tsx` → одна страница с:
- **Липкой шапкой:** `[Контекст ▾ Карточка/Главная]` · индикатор «Есть изменения»
  · плашка «Сейчас в эфире: vN» · кнопка «Опубликовать».
- **Вкладками слева:**
  - **Внешний вид** — `header.title`, цвета темы, `typography` (scale/radius/
    density), `layout` (mode/columns/pageSize), видимость элементов.
  - **Отбор отзывов** — `defaults` (minRating, marketplace, initialSort,
    requireText/Photo, onlyWithAnswer, photoFirst/textFirst), порядок
    `ranking`.
  - **Площадки** — `marketplacePolicy` по каждому МП (публичное название, ссылки
    на источник, показ/скрытие).
  - **Версии** — список + откат.
- **Постоянным превью справа** (iframe, как сейчас) + переключатель desktop/mobile
  (см. фичи).

Вся страница по-прежнему редактирует **один** объект `cfg` и публикует его целиком
одной кнопкой → модель версий не меняется. Вкладки — чисто визуальная группировка
(локальный стейт активной вкладки), не отдельные роуты.

«Витрина» (`Showcase.tsx`) остаётся отдельным пунктом меню; переформулировать
заголовок/подсказку, явно обозначив, что это **отбор отзывов для главной**, а не
оформление. Кросс-ссылка на редактор.

### 3. Система обратной связи

**Тосты.** Лёгкий модуль `src/toast.ts` (pub/sub без внешних зависимостей) +
компонент `<ToastHost>` в корне `App.tsx`. API:
```ts
toast.success(msg, action?) // action?: { label: string, onClick: () => void }
toast.error(msg, action?)
toast.info(msg, action?)
```
- Всплывают в углу, цветные по типу, авто-скрытие ~4с; ошибки — дольше или до
  клика. Могут нести кнопку-действие.
- Заменяют все `setMessage(...)` + `<p className="muted">`/`<p className="error">`
  на страницах.

**Индикатор несохранённого.** Формы держат «снимок» загруженного состояния и
сравнивают с текущим (`isDirty = !deepEqual(current, baseline)`). Пока грязно —
бейдж «Есть изменения» у кнопки + `beforeunload`-guard при уходе. После успешного
сохранения `baseline` сбрасывается на сохранённое значение. Небольшой хелпер
`useDirty(current, baseline)` или ручное сравнение (JSON) — по месту.

Затрагивает: `Editor` (cfg), `Settings`, `Showcase`, черновики доступов в
`Marketplaces`.

**«Что в эфире».** В редакторе — плашка «Сейчас в эфире: vN» (берётся из списка
версий, поле `active`). После публикации — `toast.success('Опубликована vN+1 —
уже на сайте')`.

**Разный смысл «применилось».**
- Доступы МП: `toast.success('Доступы сохранены. Запустите синхронизацию, чтобы
  подтянуть отзывы', { label: 'Синхронизировать', onClick: syncThisMp })`.
- Сниппет/Встраивание: напоминание про публикацию контейнера в Тег Менеджере.
- CORS/адрес магазина: «Применено сразу» (без рестарта).

### 4. Фичи

#### 4.1. Диагностика «Состояние» (Уровень 2)

**Размещение:** новый пункт меню **«Состояние»** (диагностика + журнал плашкой не
влезут). На «Сводке» — компактная сводка-светофор со ссылкой на страницу.

**Чек-лист (пассивный — сервер уже знает):** каждый пункт `ok | warn | fail` +
короткое «что это значит» + «как исправить» + ссылка на нужную страницу.
- Адрес магазина / CORS задан.
- Есть активная версия виджета (по контекстам).
- Экспорт свежий: когда, сколько отзывов/артикулов.
- Покрытие каталога: товаров всего, из них с отзывами.
- По каждому МП: включён, доступы заданы, последняя синхронизация + результат.
- Сколько отзывов/вопросов ждёт модерации.

**Активные проверки (сервер сам тестирует):**
- **Сайт магазина доступен** — GET по адресу магазина, вернуть статус/ошибку.
- **«Проверить страницу товара»** — поле ввода URL товара; сервер отвечает:
  страница открывается? артикул резолвится по `links.json`? есть ли для него
  видимые экспортированные отзывы? совпадает ли origin страницы с настройкой
  CORS? — прямой ответ на «почему на этой странице виджета не видно».
- **Доступы МП валидны** — лёгкий тестовый вызов API по каждому настроенному МП
  (переиспользовать шаг авторизации синхронизации, где возможно).

**Честное ограничение (в UI прямым текстом):** если сниппет вставлен через Тег
Менеджер, он подставляется в браузере — сервер, забирая HTML страницы, его **не
увидит**. Поэтому «сниппет физически на странице» сервер надёжно проверить не
может. Не выдаём ложный вердикт: по URL отдаём всё проверяемое (CORS-origin,
резолв артикула, наличие отзывов), а для сниппета — подсказку: «Если все проверки
зелёные, а виджета нет — проверьте, что контейнер в Тег Менеджере опубликован».

**Журнал (человекочитаемый).** Синхронизации, экспорт, обходы каталога, публикации
ответов — из **существующих** источников (`recent_syncs`, статусы `replyPublish`/
`answerPublish`, состояние обхода каталога). Строки вида «10:35 Обновление каталога
— ошибка: sitemap не найден по адресу …», с фильтром по важности (всё / только
проблемы). Без новой таблицы — агрегация на чтение.

#### 4.2. Бейджи-счётчики в меню

У пунктов «Отзывы» и «Вопросы» — число ожидающих модерации/ответа. Сайдбар
(`App.tsx`) подтягивает счётчики при загрузке и обновляет после действий
(например, после массовой модерации). Счётчик отзывов на модерации уже есть в
`/admin/api/dashboard`; для вопросов нужен счётчик неотвеченных.

#### 4.3. Переключатель превью desktop/mobile

В редакторе виджета — кнопка над превью, ограничивающая ширину iframe (≈390px для
mobile / полная для desktop). Чистый фронт, локальный стейт.

## Бэкенд-изменения (средний объём)

Все — в `internal/server` (обработчики админ-API). Схему БД и воркеры не трогаем.

1. **`GET /admin/api/diagnostics`** — агрегатор пассивного чек-листа: собирает
   статус CORS/настроек, активной версии виджета, свежести экспорта, покрытия
   каталога, синхронизаций по МП, счётчиков модерации. Возвращает массив пунктов
   `{ id, level: 'ok'|'warn'|'fail', title, detail, fixHref }`.
2. **`POST /admin/api/diagnostics/probe`** — активные проверки: `{ productUrl? }`
   → доступность сайта, резолв артикула по `links.json`, наличие видимых
   экспортированных отзывов, совпадение origin с CORS; плюс проверка доступов МП.
3. **`GET /admin/api/activity`** (или расширить `/dashboard`) — человекочитаемый
   журнал из существующих источников (агрегация, без новой таблицы).
4. **Счётчик неотвеченных вопросов** — добавить в `/admin/api/dashboard` (или
   лёгкий `/admin/api/counts`) для бейджей в меню.

Точные сигнатуры и переиспользование существующих эндпоинтов уточняются на этапе
плана (сверить с реальными обработчиками в `internal/server`). Активные проверки
делают исходящие запросы — предусмотреть таймаут и мягкую деградацию (проверка
недоступна ≠ падение всей диагностики).

## Тестирование

- **Бэкенд:** табличные тесты Go для новых эндпоинтов диагностики (пассивные
  вердикты при разных состояниях: CORS не задан, нет версии, экспорт протух, МП
  не настроен). Для активных проверок — мок исходящих запросов (успех/таймаут/
  4xx) и корректная мягкая деградация.
- **Фронт:** сборка `npm run build` без ошибок TS; ручная проверка ключевых
  сценариев в реальной админке (см. навык `verify`): тост при сохранении,
  индикатор несохранённого + guard, публикация версии и «в эфире», страница
  «Состояние» на инстансе с неполной настройкой, «Проверить страницу товара» на
  живом URL, бейджи-счётчики, переключатель превью.
- Прогон существующего набора (`go test ./...`) остаётся зелёным.

## Порядок реализации (черновик, детализируется планом)

1. Токены дизайн-системы + Inter локально + базовая форма (визуальный фундамент).
2. Инфраструктура тостов (`toast.ts` + `ToastHost`) и перевод страниц на неё.
3. Индикатор несохранённого + «что в эфире».
4. Вкладки «Виджета» + переключатель превью.
5. Бэкенд диагностики (пассив → актив → журнал) + счётчик вопросов.
6. Страница «Состояние» + сводка-светофор на «Сводке» + бейджи в меню.
7. Вычитка копирайта подсказок «как исправить» и ограничения по Тег Менеджеру.
